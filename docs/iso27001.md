# Seguridad — lineamientos ISO/IEC 27001 (2022)

Este documento describe **cómo el MVP aplica** los controles del Anexo A de
ISO/IEC 27001:2022 y qué queda **fuera de alcance** por tratarse de un prototipo.
No constituye una certificación ni una auditoría: es una matriz de trazabilidad
entre los requisitos y el código.

## 1. Principios rectores

- **Denegar por defecto:** toda ruta exige sesión salvo las explícitamente públicas.
- **Mínimo privilegio:** la API, el feed WebSocket y los DTO exponen solo lo que cada rol necesita.
- **No confiar en la entrada:** toda entrada externa pasa por validación Zod; todo el SQL usa parámetros.
- **Fallo seguro:** si la configuración es inválida, el proceso no arranca.
- **Trazabilidad:** toda mutación relevante queda en una bitácora de solo anexado.

## 3. Controles no aplicables o fuera de alcance (MVP)

| Control | Motivo |
| ------- | ------ |
| A.5.7 Inteligencia de amenazas, A.5.19–A.5.23 (proveedores), A.5.29–A.5.30 (continuidad) | No hay cloud ni proveedores externos; alcance de un prototipo académico. |
| A.7.x (controles físicos) | Fuera del alcance del software. |
| A.8.7 Protección contra software malicioso, A.8.12 Prevención de fuga de datos, A.8.13 Copias de seguridad | Dependen de la infraestructura de despliegue, no del código. |
| A.8.25 Ciclo de vida de desarrollo seguro | Se sigue de forma ligera; no hay proceso formal en un MVP. |

## 4. Riesgos residuales y limitaciones

- **Sin TLS por defecto.** Se asume despliegue en red privada. En producción debe
  usarse HTTPS: la cookie de sesión pasa a `Secure` y `HSTS` se activa
  automáticamente cuando `NODE_ENV=production`.
- **JWT de larga duración** (8 h) sin lista de revocación explícita; la revocación
  se logra deshabilitando la cuenta (se revalida en cada petición).
- **Un único administrador inicial** creado por `bootstrap`; hay que cambiar su
  contraseña en el primer acceso.
- **Rate limiting en memoria**: válido para un solo proceso; con varias réplicas
  requeriría un almacén compartido.
- **Bitácora sin integridad criptográfica** (no hay firma/encadenamiento); el
  control es la restricción de escritura, no la detección de manipulación.
